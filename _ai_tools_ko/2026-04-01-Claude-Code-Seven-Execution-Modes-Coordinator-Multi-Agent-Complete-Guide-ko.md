**Claude Code**는 단순히 터미널에서 동작하는 AI 챗봇이 아닙니다. 인터랙티브 모드, 스크립트 자동화, 멀티 에이전트 조율, 백그라운드 데몬, 클라우드 연결 원격 세션 등 다양한 방식으로 동작하는 **다중 실행 모드 에이전트 플랫폼**입니다. 어떤 상황에서 어떤 모드를 선택하고, 각 모드를 어떻게 설정하느냐가 일반 사용자와 파워 유저를 구분하는 핵심입니다.

이 가이드는 개발자 관점에서 실용적인 내용에 집중합니다. 각 실행 모드의 활용 시나리오, Coordinator 모드를 통한 병렬 AI 작업, Hook 시스템 자동화, Bridge 모드의 원격·멀티 디바이스 워크플로까지 다룹니다.

## 왜 실행 모드가 중요한가

Claude Code는 단일 ~800KB 모놀리식 번들(`main.tsx`)로 컴파일되어 있습니다. 시작 시 CLI 인수를 파싱하여 완전히 다른 코드 경로로 분기합니다. 선택한 모드에 따라 결정되는 것들:

- UI를 초기화할지 여부
- AI 응답이 인터랙티브하게 스트리밍될지, 조용히 배치 처리될지
- 하나의 AI 에이전트가 작동할지, 여러 에이전트가 동시에 작동할지
- 세션이 로컬에서만 실행될지, 클라우드에 연결될지

상황에 맞지 않는 모드를 선택하면 성능, 인터랙티브성, 자동화 능력을 손해봅니다. 올바른 모드를 선택하면 Claude Code가 작업 환경에 자연스럽게 통합됩니다.

## 7가지 실행 모드 상세 가이드

### 1. REPL — 기본 인터랙티브 모드

**사용 시점**: 일상적인 코딩 지원, 코드베이스 탐색, 반복적인 디버깅.

터미널에서 그냥 `claude`를 입력하면 시작되는 모드입니다. 질문하고, 수정을 요청하고, 명령을 실행하고, 지속적인 컨텍스트를 유지하면서 대화할 수 있는 REPL(Read-Eval-Print Loop) 환경을 제공합니다.

REPL은 내부적으로 지속적인 Bash 셸을 유지합니다. 즉, `cd` 명령의 디렉토리 변경이 다음 호출에도 유지되고, 환경 변수 설정도 그대로 남습니다. 이것은 설계적 결정입니다.

**REPL 모드의 핵심 기능**:
- DiffViewer와 PermissionPrompt가 포함된 완전한 React + Ink 터미널 UI
- 80개 이상의 슬래시 명령 사용 가능 (`/clear`, `/compact`, `/plan`, `/mcp` 등)
- 실시간 비용 표시 (토큰 수 + USD)
- 컨텍스트가 95%에 도달하면 자동 압축

**실전 팁**: 위험한 리팩토링 전에 `/plan`으로 계획 모드로 전환하세요. Claude가 실행 계획을 먼저 보여주고, 검토 후 승인하거나 방향을 바꿀 수 있습니다.

### 2. Headless — 파이프라인에 통합하기

**사용 시점**: CI/CD 파이프라인, 크론 잡, 셸 스크립트, 자동화된 코드 리뷰.

`-p` 플래그로 활성화합니다:

```bash
# diff 보안 검토
git diff HEAD~1 | claude -p "이 diff에서 보안 취약점을 검토해줘"

# 변경 로그 자동 생성
git log --oneline -20 | claude -p "이 커밋들로 변경 로그 항목 작성해줘"

# 다른 도구와 파이프 연결
claude -p "TODO 주석이 있는 모든 파일과 줄 번호를 나열해줘" | tee todos.txt
```

UI를 초기화하지 않습니다. 출력은 stdout/stderr로 직접 전달됩니다. 종료 코드가 성공/실패를 나타냅니다. 완전한 Unix 시민입니다.

**REPL과의 주요 차이점**:
- 단일 프롬프트 입력 후 결과 출력 — 인터랙티브 루프 없음
- React/Ink UI 없음 (낮은 오버헤드)
- 파이핑에 적합한 깔끔한 텍스트 출력
- Headless 모드에서는 기본적으로 권한이 자동 승인됨 (파괴적인 작업 주의)

**CI/CD에서**: Hook 시스템(아래 참조)과 결합하여 모든 자동화된 Claude Code 실행이 감사 추적에 기록되도록 강제할 수 있습니다.

### 3. Coordinator — 병렬 멀티 에이전트 실행

**사용 시점**: 여러 파일에 걸친 대규모 리팩토링, 병렬 작업 실행, 단일 컨텍스트 창을 초과하는 모든 작업.

Coordinator 모드는 Claude Code의 가장 강력하고 아키텍처적으로 복잡한 기능입니다. **Leader/Worker 패턴**을 구현합니다:

```
사용자 요청
    ↓
Leader 에이전트 (작업 분해)
    ↓
┌──────────────────────────────┐
│ Worker 1 │ Worker 2 │ ...N   │
│ (인증)    │ (라우트)  │ (API) │
└──────────────────────────────┘
    ↓
Leader 에이전트 (결과 종합)
    ↓
최종 결과
```

Leader는 전체 작업을 받아 분석하고 독립적인 서브태스크로 분해합니다. 각 서브태스크는 전담 Worker에게 할당됩니다. Worker는 자체 컨텍스트 창을 가진 독립적인 완전한 Claude Code 인스턴스입니다. Workers는 병렬로 실행되며, 각각 완전한 도구 시스템(Bash, 파일 작업, 웹 검색 등)에 접근할 수 있습니다. Leader는 결과를 수집하고 최종 출력을 종합합니다.

**통신은 구조화되어 있습니다**: Workers는 JSON 형식의 작업 정의를 받고 JSON 결과를 반환합니다. 에이전트 간에 자유 형식 텍스트가 아닌 구조화된 데이터만 사용합니다. 이는 단순한 멀티 에이전트 시스템에서 발생하는 "전달 게임" 품질 저하를 방지합니다.

**실제 활용 사례**:

*대규모 리팩토링*: "이 50개 파일 코드베이스 전체에서 API 호출을 v1에서 v2 엔드포인트로 마이그레이션해줘." Leader가 파일 그룹을 Workers에게 할당합니다. 각 Worker가 독립적으로 파일을 처리합니다. 총 소요 시간은 50개 파일이 아닌 파일 1개를 처리하는 시간과 비슷합니다.

*병렬 테스트 생성*: "`src/`의 모든 모듈에 대한 단위 테스트를 작성해줘." Workers가 각 모듈을 하나씩 담당하여 동시에 실행합니다.

*다국어 문서화*: "모든 API 문서를 한국어, 영어, 일본어로 번역해줘." 세 Workers, 세 언어, 동시 실행.

**설정**: settings.json에서 최대 Worker 수를 설정하세요. Workers가 많을수록 병렬 API 호출이 증가하여 처리량은 높아지지만 분당 비용도 증가합니다.

### 4. Bridge — 로컬 터미널, 원격 제어

**사용 시점**: 멀티 디바이스 워크플로, 모바일 감독, 공유 페어 프로그래밍 세션.

Bridge 모드는 로컬 Claude Code 터미널 세션과 Anthropic의 CCR(Claude Code Remote) 클라우드 인프라 사이에 **WebSocket 연결**을 설정합니다. 로컬 머신이 실행 환경으로 유지되고, 클라우드가 연결 레이어를 제공합니다.

```bash
claude --bridge  # Bridge 모드 시작, 세션 URL 출력
```

최대 **32개의 병렬 세션**을 동시에 브리지할 수 있습니다. 여러 사람이 실행 중인 Claude Code 세션을 감독하거나 상호작용해야 하는 팀에게 유용합니다.

**실용적인 시나리오**:

*모바일 감독*: 회의 전에 노트북에서 대규모 리팩토링을 시작했습니다. 회의 중 스마트폰으로 세션 URL을 열면 진행 상황을 확인하고, Claude의 질문에 답하고, 방향을 조정할 수 있습니다.

*디바이스 인계*: 회사에서 디버깅 세션을 시작하고 집에서 URL을 통해 이어서 작업합니다. 전체 컨텍스트가 보존됩니다.

*페어 프로그래밍*: 동료에게 세션 URL을 공유합니다. 두 사람 모두 같은 세션을 보고 상호작용할 수 있습니다.

**참고**: Bridge 모드는 CCR이 활성화된 Anthropic 계정이 필요합니다.

### 5. Kairos — 스케줄된 AI 작업

**사용 시점**: 반복적인 코드 유지 보수 작업, 야간 검토, 자동화된 정기 작업.

Kairos 모드는 Claude Code의 "스마트 크론"입니다. 정적 셸 스크립트를 스케줄링하는 대신, 자연어로 원하는 작업을 설명하여 스케줄링합니다.

```bash
claude --kairos "매주 월요일 오전 9시: 이번 주 추가된 TODO 주석을 검토하고 GitHub 이슈 생성"
```

Kairos는 예약된 시간에 전체 Claude Code 기능으로 작업을 실행합니다. 파일 읽기, 테스트 실행, 커밋 작성, 이슈 생성 등 모든 것이 가능합니다.

**활용 사례**:
- 주간 "의존성 감사" — 오래된 패키지 확인, 업데이트 PR 생성
- 야간 "문서 불일치 감지" — 코드와 문서 비교, 불일치 플래그 표시
- 일일 "테스트 건강 상태" — 전체 테스트 스위트 실행, 실패 요약을 Slack 메시지로 전송

### 6. Daemon — 에디터 통합을 위한 백그라운드 서비스

**사용 시점**: 에디터 플러그인 통합, IDE 확장, 빠른 요청을 많이 처리하는 시나리오.

Daemon 모드는 Claude Code를 로컬 소켓 또는 IPC 채널을 통해 요청을 받는 지속적인 백그라운드 서비스로 실행합니다. 핵심 이점: 시작 비용(모놀리스 로드, MCP 연결 초기화, 컨텍스트 가져오기)이 한 번만 발생하고 여러 요청에 걸쳐 분산됩니다.

코딩 세션당 50번의 요청을 보내는 에디터 확장의 경우, "요청마다 새 프로세스 시작"과 "지속적인 데몬에 전송"의 차이는 지연 시간과 리소스 사용량 모두에서 상당합니다.

### 7. Viewer — 읽기 전용 세션 관찰자

**사용 시점**: 실행 중인 세션 디버깅, AI 작업 감사, 데모.

Viewer 모드는 활성 Claude Code 세션에 연결하여 진행 상황(도구 호출, AI 응답, 권한 프롬프트)을 표시하지만 명령을 보내거나 상호작용할 수 없습니다. Claude Code 세션의 `tail -f` 같은 것입니다.

**활용 사례**:
- 감사: 민감한 환경에서 Claude Code가 하는 일을 보안팀이 모니터링
- 디버깅: 코디네이터 세션이 예상대로 동작하지 않는 이유 파악
- 데모: 실수로 명령이 실행될 위험 없이 Claude Code 동작 시연

## Hook 시스템: 자동화의 핵심 기능

Hook은 Claude Code의 간과하기 쉬운 강력한 기능입니다. 실행 라이프사이클의 핵심 지점에 셸 명령을 주입하여 Claude Code 코드를 수정하지 않고도 자동화를 구현할 수 있습니다.

**4가지 Hook 타입**:

### `PreToolUse` — 도구 실행 전
어떤 도구 실행 전에도 실행됩니다. 비제로 종료 코드를 반환하여 도구 호출을 중단할 수 있습니다.

```json
{
  "hooks": {
    "PreToolUse": "echo '{\"tool\": \"$TOOL_NAME\", \"time\": \"$(date -u +%Y-%m-%dT%H:%M:%SZ)\"}' >> ~/.claude/audit.log"
  }
}
```

이것은 모든 도구 호출을 감사 추적에 기록합니다. 컴플라이언스 환경에 유용합니다.

**중단 예시**: JIRA 티켓 참조 없이 Claude Code의 `git push`를 차단:

```bash
#!/bin/bash
# pre-push-check.sh
if [ "$TOOL_NAME" = "Bash" ] && echo "$TOOL_INPUT" | grep -q "git push"; then
  if ! echo "$TOOL_INPUT" | grep -qE "PROJ-[0-9]+"; then
    echo "오류: git push에는 JIRA 티켓 참조가 필요합니다"
    exit 1
  fi
fi
```

### `PostToolUse` — 도구 완료 후
도구가 완료된 후 실행됩니다. 결과를 검사하고 외부 작업을 트리거할 수 있습니다.

### `UserPromptSubmit` — AI에게 메시지 전송 전
사용자 메시지가 AI에게 전달되기 전에 실행됩니다. 컨텍스트를 자동으로 추가할 수 있습니다.

```bash
#!/bin/bash
# 모든 프롬프트에 현재 git 브랜치를 자동 추가
echo "현재 브랜치: $(git rev-parse --abbrev-ref HEAD)"
```

### `Stop` — 세션 종료 시
세션이 종료될 때 실행됩니다. 정리, 요약 저장, 알림 전송에 사용합니다.

```json
{
  "hooks": {
    "Stop": "~/.claude/scripts/session-summary.sh | mail -s 'Claude Code 세션 요약' you@company.com"
  }
}
```

Hook은 `~/.claude/settings.json`(전역) 또는 `.claude/settings.json`(프로젝트 수준)에 정의됩니다. 프로젝트 Hook은 코드와 함께 커밋되므로 팀 전체가 동일하게 적용받습니다.

## 권한 모드: 신뢰 수준에 맞게 설정하기

실행 모드 선택과 함께 **권한 모드**도 중요한 설정입니다:

| 모드 | 인터랙티브? | 안전 작업 자동 승인? | 위험 작업 확인 필요? |
|------|------------|---------------------|---------------------|
| Default | Yes | No | Yes |
| Auto | Yes | Yes | Yes |
| Plan | Yes | N/A | N/A (실행 없음) |
| Bypass (`--dangerously-skip-permissions`) | No | Yes | No |

**Headless CI/CD용**: 적절히 샌드박스된 컨테이너 내부에서만 Bypass 모드를 사용하세요. 플래그 이름이 의도적으로 경고를 주는 형태로 되어 있습니다.

**인터랙티브 REPL용**: 편안함 수준에 따라 Default 또는 Auto를 선택하세요. Auto는 "파일 읽기/쓰기는 신뢰하지만 셸 실행은 확인하고 싶다"는 경우에 좋습니다.

**대규모 리팩토링 전 코드 검토용**: Plan 모드로 계획을 검토한 다음, 실행을 위해 Auto나 Default로 재실행합니다.

## 결론

Claude Code의 7가지 실행 모드는 임의적인 것이 아닙니다. 인터랙티브, 자동화, 병렬, 원격, 스케줄, 지속적, 읽기 전용이라는 모든 주요 개발자 워크플로를 커버하는 신중하게 설계된 솔루션 공간입니다. 올바른 모드와 Hook, 적절한 권한 수준을 결합하면 Claude Code가 단순한 챗봇에서 자동화된 엔지니어링 협업자로 변모합니다.

특히 Coordinator 모드는 AI 코딩 어시스턴트가 할 수 있는 것의 수준을 한 단계 높여줍니다. 하나의 컨텍스트 창에서 하나의 AI가 작동하는 대신, 여러 AI가 병렬로 작동하고 각각 전문화되어 Leader가 출력을 종합합니다. 대규모 코드베이스와 복잡한 작업에서 이것은 "AI 보조"와 "AI 가속"의 차이를 만듭니다.
