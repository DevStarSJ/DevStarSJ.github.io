# Cursor: 프로그래밍 방식을 바꾸는 AI 퍼스트 코드 에디터

![컬러풀한 구문 강조가 있는 코드 에디터 화면](https://images.unsplash.com/photo-1555066931-4365d14bab8c?w=800)
*Photo by [Luca Bravo](https://unsplash.com/@lucabravo) on Unsplash*

GitHub Copilot이 있습니다 — 기존 에디터에 자동완성을 추가하는 플러그인이죠. 그리고 **Cursor**가 있습니다 — AI를 플러그인이 아닌 기반으로 삼아 AI를 중심으로 처음부터 재구축된 코드 에디터입니다. 하루에 몇 시간 이상 코드를 작성하는 개발자라면, Cursor는 올해 도입할 수 있는 가장 큰 영향력을 가진 도구일 것입니다.

## Cursor란 무엇인가요?

Cursor는 **VS Code의 포크로 구축된 AI 퍼스트 코드 에디터**입니다. 이는 다음을 의미합니다:

- 모든 VS Code 익스텐션이 네이티브로 작동
- 친숙한 키보드 단축키와 인터페이스
- 단순한 자동완성을 훨씬 넘어서는 깊은 AI 통합
- 모든 AI 상호작용을 위한 코드베이스 전체 컨텍스트

Copilot이 VS Code에 AI를 추가한다면, Cursor는 *AI가 모든 레이어에 내장된* VS Code입니다. 결과는 근본적으로 다른 코딩 경험입니다.

## 핵심 기능

### 1. Tab — 예측적 다중 라인 완성

Cursor Tab은 에디터의 시그니처 기능으로 단일 라인 제안을 훨씬 넘어서는 자동완성 시스템입니다:

- **다중 라인 예측**: 다음 토큰이 아닌 전체 블록을 예측
- **diff 인식 제안**: 방금 변경한 내용을 알고 논리적인 다음 편집을 제안
- **커서 예측**: 커서가 다음에 이동할 위치를 예측하고 해당 편집을 미리 채움
- **스마트 컨텍스트**: 최근 편집, 열린 파일, 프로젝트 구조를 고려

예측을 수락하려면 `Tab`을 누르세요. 에디터가 문법만이 아니라 의도를 파악한 것처럼 느껴지는 경험입니다.

### 2. Chat — 전체 코드베이스를 아는 AI

Cursor Chat (`Cmd+L` / `Ctrl+L`)은 전체 코드베이스에 접근할 수 있는 AI 채팅 패널을 엽니다:

```
사용자: AuthService가 무엇을 하고 어디서 사용되나요?

Cursor: AuthService (src/services/auth.service.ts)는 JWT 토큰 
생성, 검증, 갱신을 처리합니다. 다음에 주입됩니다:
- UsersController (엔드포인트 3개)
- MiddlewareAuth (보호된 라우트용)
- WebSocketGateway (소켓 인증용)
주요 흐름은: 로그인 → 토큰 생성 → 리프레시 토큰 저장...
```

이것은 일반적인 답변이 아닙니다. Cursor는 실제 코드베이스를 인덱싱하고 그 컨텍스트에서 답변합니다.

**주요 Chat 기능:**
- **@file**: 질문에서 특정 파일 참조 (`@src/users/users.service.ts`)
- **@code**: 특정 함수나 클래스 참조
- **@docs**: 사용하는 라이브러리의 문서 가져오기
- **@web**: 추가 컨텍스트를 위한 웹 검색
- **@codebase**: 전체 프로젝트에 관한 모든 것을 질문

### 3. Composer — 다중 파일 코드 생성

Composer (`Cmd+I` / `Ctrl+I`)는 가장 강력한 기능입니다: 여러 파일에 걸쳐 동시에 조율된 편집을 하는 AI입니다:

**예시 워크플로:**
```
사용자: "사용자 환경설정 시스템을 추가해주세요. 사용자가 테마(라이트/다크)와 
알림 설정을 지정할 수 있어야 합니다. 데이터베이스 마이그레이션, 서비스 레이어, 
컨트롤러 엔드포인트, 프론트엔드 폼을 포함해주세요."

Cursor: 다음 변경사항을 생성합니다:
→ migrations/add-user-preferences.sql (신규)
→ models/UserPreferences.ts (신규)
→ services/preferences.service.ts (신규)
→ controllers/preferences.controller.ts (신규)
→ frontend/components/PreferencesForm.tsx (신규)
→ App.tsx (수정 - 환경설정 라우트 추가)
[모든 변경사항 미리보기]
```

Composer는 적용하기 전에 영향받는 모든 파일의 diff를 보여줍니다. 검토 후 개별 변경사항을 수락하거나 거부할 수 있습니다.

### 4. 인라인 편집 (`Cmd+K`)

코드를 선택하고, `Cmd+K`를 누르고, 자연어로 변경 사항을 설명합니다:

- "이것을 콜백 대신 async/await를 사용하도록 리팩토링해 주세요"
- "이 함수에 오류 처리와 로깅을 추가해 주세요"
- "이 클래스 컴포넌트를 훅이 있는 함수형 컴포넌트로 변환해 주세요"
- "이 SQL 쿼리를 최적화해 주세요 — N+1 문제가 발생하고 있습니다"

AI가 인라인으로 편집하고, 인라인 수락/거부 컨트롤과 함께 diff를 볼 수 있습니다.

## 시작하기

### 설치

1. [cursor.sh](https://cursor.sh)에서 다운로드
2. 첫 실행 시 클릭 한 번으로 VS Code 설정(익스텐션, 키바인딩, 테마) 가져오기
3. AI 모델 선택 (Claude 3.5 Sonnet이 권장 기본값)
4. 코딩 시작

가져오기 단계가 핵심입니다 — 모든 VS Code 설정을 즉시 가져오므로 설정 마찰이 거의 없습니다.

### 코드베이스 인덱싱

Chat과 Composer가 코드베이스와 함께 작동하려면:

1. 프로젝트 폴더 열기
2. Cursor가 백그라운드에서 자동으로 인덱싱
3. 상태 표시줄의 스피너로 인덱싱 진행 상황 확인
4. 완료되면 AI가 프로젝트 전체 컨텍스트를 보유

대규모 코드베이스 (100K+ 파일)는 몇 분 내에 인덱싱됩니다. 편집 시 인덱스가 최신 상태로 유지됩니다.

### 모델 선택

Cursor는 여러 AI 모델을 지원합니다:

| 모델 | 최적 용도 | 속도 |
|------|---------|------|
| claude-3-5-sonnet | 일반 코딩, 복잡한 작업 | 빠름 |
| gpt-4o | 대안 옵션, 광범위한 지식 | 빠름 |
| claude-3-7-sonnet | 확장 사고가 있는 어려운 문제 | 느림 |
| cursor-small | 간단한 완성, 빠른 응답 | 매우 빠름 |

채팅 패널의 드롭다운을 사용하여 채팅별로 모델을 전환합니다.

## Cursor vs. GitHub Copilot

모두가 묻는 비교:

| 기능 | Cursor | GitHub Copilot |
|------|--------|---------------|
| 에디터 | 내장 (VS Code 포크) | VS Code 플러그인 + 기타 |
| 코드베이스 컨텍스트 | 전체 프로젝트 인덱싱 | 제한된 컨텍스트 |
| 다중 파일 생성 | ✅ Composer | ❌ |
| 인라인 AI 채팅 | ✅ | ✅ |
| 모델 선택 | 다양 (Claude, GPT-4) | GPT-4 기반 |
| 가격 | Pro $20/월 | 개인 $10/월 |
| VS Code 익스텐션 | 모두 작동 | 모두 작동 |
| 프라이버시 모드 | ✅ | ✅ |

**Copilot이 유리한 경우**: 기존 VS Code 설정을 그대로 유지하거나 VS Code 이외의 에디터(JetBrains, Neovim) 사용 시

**Cursor가 유리한 경우**: 가장 깊은 AI 통합, 코드베이스 전체 컨텍스트, 다중 파일 생성을 원할 때

## 요금제

| 플랜 | 가격 | 기능 |
|------|------|------|
| 무료 | $0 | 월 2,000회 완성, 50개의 느린 요청 |
| Pro | $20/월 | 무제한 완성, 월 500개의 빠른 요청, 모든 모델 |
| Business | 사용자당 $40/월 | 팀 기능, 프라이버시 보장, 관리자 컨트롤 |

**Pro 플랜은 일상적인 사용의 현실적인 시작점**입니다. 500개의 빠른 요청은 대부분의 워크플로우에 충분합니다 — Composer에 크게 의존하는 파워 유저는 한도에 도달할 수 있습니다.

## 프라이버시 및 보안

전문 개발자의 일반적인 걱정:

**프라이버시 모드** (설정에서 활성화):
- 코드는 AI 모델 훈련에 절대 사용되지 않음
- 요청이 저장되지 않음
- 대부분의 기업 보안 정책 준수

기본 설정 (프라이버시 모드 없이):
- 코드가 Cursor의 모델 개선에 사용될 수 있음
- 민감한 코드베이스에서 사용하기 전에 회사 정책 검토

기업 팀의 경우 Business 플랜은 더 강력한 데이터 처리 계약을 포함합니다.

## 실제 워크플로우: Cursor와 함께하는 하루

**오전: 새 기능 시작**

Composer에서 기능을 설명합니다. Cursor가 파일을 스캐폴딩하고, 데이터베이스 스키마를 생성하고, 테스트 스텁을 작성하고, 라우트를 설정합니다. diff를 검토하고 맞는 것을 수락합니다. 30분의 설정 작업이 5분으로 단축됩니다.

**오전 중반: 까다로운 이슈 디버깅**

Chat에 오류를 붙여넣고, `@auth.service.ts`를 입력하고, 무엇이 원인일 수 있는지 묻습니다. Cursor가 실제 파일을 읽고 실제 코드 구조를 참조하여 구체적인 설명을 제공합니다.

**오후: 코드 리뷰 준비**

복잡한 함수를 선택하고 Cmd+K를 사용하여 포괄적인 JSDoc 주석을 추가합니다. 그런 다음 Composer를 사용하여 전체 모듈에 대한 단위 테스트를 작성합니다. 수동으로 작성하면 한 시간이 걸릴 테스트가 1분 이내에 나타납니다.

**하루 마무리: 리팩토링**

Composer에 지저분한 레거시 모듈을 리팩토링해 달라고 요청합니다 — 더 작은 서비스로 분리하고, 누락된 TypeScript 타입을 추가하고, 모든 import 경로를 업데이트합니다. 12개 파일에 걸친 diff를 보여줍니다. 검토하고, 두 파일을 수동으로 조정한 다음, 나머지를 수락합니다.

## Cursor를 최대한 활용하는 팁

1. **프롬프트를 구체적으로**: "오류 처리 추가"는 약합니다. "try-catch 블록을 추가하고, winston으로 에러 레벨에서 오류를 로그하고, 표준화된 ApiError 응답을 반환"은 강합니다.

2. **@참조를 적극 활용**: @file과 @code를 통해 더 많은 컨텍스트를 줄수록 출력이 좋아집니다.

3. **Composer diff를 주의깊게 검토**: Cursor의 다중 파일 변경은 강력하지만 가끔 엣지 케이스를 놓칠 수 있습니다. 수락 전에 항상 검토하세요.

4. **코드 옆에 Chat 열어두기**: 실제로 코드베이스를 아는 "고무 오리"로 사용하세요.

5. **`.cursorrules` 활용**: 프로젝트 루트에 `.cursorrules` 파일을 만들어 프로젝트별 AI 동작을 설정하세요:
   ```
   TypeScript strict 모드를 사용하는 Next.js 14 앱입니다.
   클라이언트 인터랙티비티가 필요하지 않는 한 항상 서버 컴포넌트를 사용하세요.
   오류 처리에는 저장소의 기존 패턴을 따르세요.
   입력 검증에는 Zod를 사용하세요. 모든 새 유틸리티에 Jest 테스트를 작성하세요.
   ```

## 한계

- **대규모 비용**: Composer를 많이 사용하면 500개의 빠른 요청 한도를 소진할 수 있음
- **컨텍스트 한계**: 코드베이스 인덱싱이 있어도 매우 큰 프로젝트는 컨텍스트에 완전히 맞지 않을 수 있음
- **정확도**: 모든 AI 코딩 도구처럼 Cursor도 실수를 합니다 — 커밋 전에 항상 생성된 코드를 검토하세요
- **벤더 락인**: Cursor 특화 워크플로우 (`.cursorrules`, Composer)는 다른 에디터로 이전되지 않음

## 결론

Cursor는 코딩 환경의 다음 진화를 대표합니다. AI가 추가된 기능이 아니라 AI를 핵심으로 설계된 에디터입니다. Tab, Chat, Composer를 조합하여 완전히 도입하는 개발자에게 생산성 향상은 이론적인 것이 아니라 실질적이고 실재합니다.

Cursor를 이해하는 가장 좋은 방법은 사용해 보는 것입니다. VS Code 설정을 가져오고, 활발히 작업 중인 프로젝트를 열어 하루 동안 코딩해 보세요. 그렇게 한 대부분의 개발자는 돌아가지 않습니다.
